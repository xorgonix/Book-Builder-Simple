# Module 1: Database Schema & Core Storage Subsystem (Un-Flattened)

## 1. Initialization & Migration Architecture
Database collections must be constructed programmatically using native PocketBase migration hooks (`migrations/000001_initial_schema.go`). On the initial application boot, the framework evaluates the local database instance and applies these strict schemas to guarantee relational integrity before booting up the HTTP listeners.

## 2. Canonical Table Layouts & Structs

### Table A: `projects`
Manages high-level project states, global target configurations, and the core style profile.
```go
type Project struct {
	Id             string `json:"id"`
	Title          string `json:"title"`
	BookType       string `json:"type"`                // "fiction" | "nonfiction"
	Status         string `json:"status"`              // See SPEC_MASTER.md §4.A
	TargetLength   string `json:"target_length"`       // "short_guide" | "practical_ebook" | "full_prototype"
	TargetChapters int    `json:"target_chapters"`     // Integer constraint (e.g., 10, 12, 15)
	UIState        string `json:"ui_state"`           // Canonical JSON string (see SPEC_MASTER.md §4.C)
	VoiceCard      string `json:"voice_card"`          // Persistent style profile generated by the Voice Card Builder
	Created        string `json:"created"`
	Updated        string `json:"updated"`
}


### Table B: `intake_responses`

Tracks individual user questionnaire answers. Enforces the psychological foundation metrics required to ensure the generated text matches the author's target vision. One row per unique `(project_id, key)` pair.

Go

```
type IntakeResponse struct {
	Id        string `json:"id"`
	ProjectId string `json:"project_id"` // Managed Relation: Cascade Delete
	Key       string `json:"key"`        // Authorized Key Vocabulary list below
	Value     string `json:"value"`      // Long text text block
}
```

#### Authorized Questionnaire Keys:

- `core_topic`: What is the book explicitly about?
    
- `target_audience`: Who is this book written for?
    
- `reader_hunger`: What specific pain, question, desire, confusion, or ambition brings this reader to the book? _(The Killer Question)_
    
- `prohibited_directions`: What should this book absolutely **not** become? _(The Anti-Mush Constraint)_
    
- `author_intent`: What should the reader be able to do, understand, or feel after reading?
    
- `selected_tone`: The voice profile target (e.g., Warm, Direct, Credible, Irreverent).

## 3. Relational Constraints & Validation Logic

The Go database layer must implement validation rules inside the PocketBase collection hook interceptors (`app.OnModelBeforeCreate` and `app.OnModelBeforeUpdate`):

### A. Strict Sequential Integrity (No Outline Gaps)

Before committing any changes to a record inside the `chapters` collection, the backend must evaluate the `sort_order` array sequence for that specific project.

- If an item is dropped, deleted, or assigned a new position, the sequence indexes for all adjacent elements must reconcile automatically.
    
- The `sort_order` values must remain a dense, continuous positive sequence with no arbitrary numerical jumps ($1, 2, 3, 4\dots$).
    

### B. Project Status Guardrails

Reject any manual or malformed attempts to write illegal combinations directly to the database.

- A project cannot shift out of `intake` unless its parent `projects` row contains verified values for both `target_length` and `target_chapters`.
    
- A project cannot skip steps in the core wizard sequence (e.g., moving directly from `intake` to `toc` without a verified row in `book_briefs`).
